# 全面审查与改进记录（2026-10-27）

审查对象：第 19 版（`5a99f77` 之后，导览主线与支线 A–G 已在该版本上重走）。目标是判断 Kairoz 作为**可运行产品原型**是否达到目的：让各角色在浏览器里完整走通 v0.13 设计的协作流程，从而验证产品设计。

## 方法

四个互不依赖的视角，各自只读：

| 视角 | 做法 | 编号 |
|---|---|---|
| 需求覆盖 | 对照 v0.13 设计文档（设计稿、生命周期、主流程、工作区与资源、RBAC、环境与回执、数据使用、客户端上报、剧本手册），逐领域核对代码与验收证据 | R1–R20 |
| 规则正确性 | 通读 `src/domain`、`src/engine`，每条问题都写了复现脚本并确认今天失败 | E1–E16 |
| 产品与界面 | 逐页核对各角色的入口、链接、用词、格式、空状态、可访问性与前端性能 | U1–U20 |
| 自查 | 导览重走时的观察、持久化与状态体积 | K1–K6 |

## 结论

**达到目标，但有三处必须补上才能放心交给评审者使用。**

- 九类角色都能从头走到尾：从零启动 → 普通与敏感 Feature → 集成与冲突修复 → 正式发布与配置 OTA → 事件与数据使用 → 异常恢复。20 份剧本在引擎层重放 214 幕通过、0 失败、3 幕不适用（服务器部署）；导览主线与支线在第 19 版上逐步点过，全量走查 17,229 个中英文视图无问题。
- 规则核心稳固：单条完整授权、一次操作一个事务、回执、合并与测试证据规则一致，没有找到拼接授权或留下半截状态的路径。
- 问题集中在功能交界处：
  1. **量产安全**：OTA 包内配置模块绕过了“只有回执改变车辆运行内容”的模型（E1、E2、E4、E6、E9）；灰度结果出来前就能扩量（R1）；回滚失败后无法继续（E5）。这些正是配置发布角色要验证的风险控制。
  2. **导航上下文**：跨工作区的角色登录后落在没有待办的工作区，Feature 链接与部分按钮通向无权页面，深链接落在默认分页（U1–U4、K3）。评审者会把它当成功能缺失。
  3. **v0.13 主打的多车型独立发布没有被走过**（R4）。

## 发现

### 规则（E）

| 编号 | 级别 | 问题 | 位置 |
|---|---|---|---|
| E1 | 高 | 对已在运行的软件版本再次确认，车辆被换回 OTA 包内的旧配置模块（无回执、无 OTA） | `engine/fleet.ts` `applyBundledModule` |
| E2 | 高 | 运行包内模块的车辆产生的事件不属于任何工作区，所有人都看不到 | `engine/events.ts` `sourceWorkspace` |
| E3 | 高 | 征集的模块记录变化（不参加、重交、本次无变更）不关闭正在测试的一轮，发布的策略集与征集记录矛盾 | `engine/calls.ts`、`integration.ts` `freezeCandidate` |
| E4 | 中高 | 车辆软件变化后，旧的配置 OTA 回执仍被接受，车辆运行不适用其软件的策略集 | `engine/validation.ts` `acceptReceipt` |
| E5 | 中 | 回滚 OTA 因单车失败暂停后无法恢复，也无法重建 | `engine/ota.ts` `resumeOta` |
| E6 | 中 | 策略集已撤回适用或被紧急停用后，包内模块仍被应用 | `engine/fleet.ts` |
| E7 | 中 | 归档发布了在用策略集的工作区后，紧急停用无法发起 | `engine/lifecycle.ts` |
| E8 | 中 | 有未结束集成征集的集成工作区可以归档 | `engine/lifecycle.ts` |
| E9 | 中低 | 量产车经自身签名上报被记录到规划中的版本 | `engine/software-change.ts` |
| E10 | 中低 | 改目标版本跳过“版本已发布”检查 | `engine/calls.ts` `retargetCall` |
| E11 | 低 | 整车征集发布后域子征集仍开着；可为“不参加”的模块开子征集 | `engine/calls.ts` |
| E12 | 低 | 改目标版本删除了待更新车辆指向的规划版本 | `engine/calls.ts` `retargetCall` |
| E13 | 低 | 撤回团队测试申请没有授权检查与审计 | `engine/validation.ts` `withdrawTestRequest` |
| E14 | 低 | schema 21 迁移把旧 OTA 目标标成车辆当前软件 | `engine/migrate.ts` |
| E15 | 低 | 发布记录丢失被后续操作覆盖的步骤（模块再导出、规划→登记） | `engine/calls.ts`、`history.ts` |
| E16 | 低 | 归档检查还漏了未结束的适用性测试、团队测试申请与待批准的紧急停用（同 E7、E8 一类） | `engine/lifecycle.ts` |

| 轮 | 内容 | 状态 |
|---|---|---|
